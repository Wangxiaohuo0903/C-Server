### 5.1.5 编写Dockerfile

创建 `Dockerfile.nomodel`：

```dockerfile
# ===== 第一阶段：编译llama.cpp =====
FROM ubuntu:22.04 AS llama-builder

# 避免交互式提示
ENV DEBIAN_FRONTEND=noninteractive

# 安装编译依赖
RUN apt-get update && apt-get install -y \
    build-essential \
    cmake \
    git \
    && rm -rf /var/lib/apt/lists/*

# 复制llama.cpp源码
WORKDIR /build
COPY third_party/llama.cpp /build/llama.cpp

# 编译llama.cpp
RUN cd llama.cpp && \
    cmake -B build -DCMAKE_BUILD_TYPE=Release && \
    cmake --build build --config Release -j$(nproc)

# ===== 第二阶段：运行环境 =====
FROM ubuntu:22.04

ENV DEBIAN_FRONTEND=noninteractive

# 安装运行时依赖
RUN apt-get update && apt-get install -y \
    libsqlite3-dev \
    libgomp1 \
    && rm -rf /var/lib/apt/lists/*

# 创建工作目录
WORKDIR /app

# 从构建阶段复制llama.cpp库
COPY --from=llama-builder /build/llama.cpp/build/bin /app/third_party/llama.cpp/build/bin
COPY --from=llama-builder /build/llama.cpp/include /app/third_party/llama.cpp/include
COPY --from=llama-builder /build/llama.cpp/ggml/include /app/third_party/llama.cpp/ggml/include

# 复制Server-11源码
COPY main.cpp .
COPY SimpleInference.h .
COPY users.db .

# 编译Server-11
RUN g++ main.cpp -o server11 \
    -I/app/third_party/llama.cpp/include \
    -I/app/third_party/llama.cpp/ggml/include \
    -L/app/third_party/llama.cpp/build/bin \
    -lllama \
    -lggml \
    -lsqlite3 \
    -lpthread \
    -std=c++11 \
    -O2

# 设置库搜索路径
ENV LD_LIBRARY_PATH=/app/third_party/llama.cpp/build/bin:${LD_LIBRARY_PATH}

# 暴露端口
EXPOSE 8081

# 启动命令
CMD ["./server11", "8081", "models/smollm-360m-q4.gguf"]
```

**关键点解读**：

1. **多阶段构建**：
   - `llama-builder`：仅用于编译，包含300MB+的编译工具
   - 最终镜像：仅包含运行时依赖，减小约500MB

2. **`-j$(nproc)`**：
   ```bash
   cmake --build build -j$(nproc)
   # $(nproc) 返回CPU核心数
   # -j4 表示使用4个并行任务编译
   # 可将编译时间从5分钟缩短到2分钟
   ```

3. **`-O2`优化**：
   ```bash
   g++ main.cpp -o server11 -O2
   # -O0: 无优化（调试用）
   # -O1: 基础优化
   # -O2: 推荐优化（性能提升20-30%）
   # -O3: 激进优化（可能增大二进制大小）
   ```

### 5.1.6 编写docker-compose.yml

创建 `docker-compose.yml`：

```yaml
version: '3.8'

services:
  server11:
    build:
      context: .
      dockerfile: Dockerfile.nomodel
    image: server11:latest
    container_name: server11_container
    ports:
      - "8082:8081"
    volumes:
      - ./models:/app/models:ro
    environment:
      - MODEL_PATH=/app/models/smollm-360m-q4.gguf
    restart: unless-stopped
    deploy:
      resources:
        limits:
          cpus: '4.0'
          memory: 2G
        reservations:
          memory: 512M
```

**新增配置：资源限制**

```yaml
deploy:
  resources:
    limits:
      cpus: '4.0'      # 最多使用4个CPU核心
      memory: 2G       # 最多使用2GB内存
    reservations:
      memory: 512M     # 至少保留512MB内存
```

**为什么需要资源限制？**

```bash
# 无限制时（危险）
$ docker stats server11_container
CONTAINER        CPU %    MEM USAGE / LIMIT
server11         250%     3.5GiB / 15.6GiB  # 可能占满所有资源

# 有限制时（安全）
$ docker stats server11_container
CONTAINER        CPU %    MEM USAGE / LIMIT
server11         200%     1.8GiB / 2GiB     # 限制在可控范围
```

## 5.2 常见问题排查

在实际部署中，你可能会遇到各种问题。让我们逐一解决。

### 5.2.1 编译错误

**问题1：找不到llama.h**

```bash
error: llama.h: No such file or directory
   13 | #include <llama.h>
      |          ^~~~~~~~~~
```

**原因**：llama.cpp未正确复制，或路径配置错误

**解决方案**：

```bash
# 检查llama.cpp是否存在
$ ls third_party/llama.cpp/include/llama.h
# 如果不存在，重新复制
$ cp -r ../../AI-infra/third_party/llama.cpp ./third_party/

# 检查Dockerfile中的路径
$ grep "COPY third_party/llama.cpp" Dockerfile.nomodel
COPY third_party/llama.cpp /build/llama.cpp  # ✅ 应该有这一行
```

**问题2：链接错误**

```bash
/usr/bin/ld: cannot find -lllama
/usr/bin/ld: cannot find -lggml
```

**原因**：库文件路径不正确

**解决方案**：

```bash
# 进入容器检查库文件位置
$ docker run -it --rm server11:latest /bin/bash
root@container:/app# find /app -name "*.so"
/app/third_party/llama.cpp/build/bin/libllama.so
/app/third_party/llama.cpp/build/bin/libggml.so

# 确认Dockerfile中的-L路径正确
-L/app/third_party/llama.cpp/build/bin  # ✅ 应该指向bin目录
```

**问题3：API不兼容**

```bash
error: 'llama_get_kv_cache_used_cells' was not declared in this scope
```

**原因**：llama.cpp版本太新

**解决方案**：

```bash
# 使用AI-infra的兼容版本
$ cd third_party/llama.cpp
$ git log -1 --oneline
ece0f5c Fix compatibility  # ✅ 应该是这个commit

# 如果不是，回退到兼容版本
$ git checkout ece0f5c
$ cd ../..

# 重新构建
$ docker-compose build --no-cache
```

```bash
ports:
  - "8083:8081"  # 改为8083

# 重新启动
$ docker-compose up -d
```

**问题9：并发请求时响应很慢**

```bash
# 单个请求：8秒
$ time curl http://localhost:8082/infer -d '{"prompt": "Test", "max_tokens": 10}'
real    0m8.234s

# 并发10个请求：每个都需要80秒！
$ ab -n 10 -c 10 -p data.json http://localhost:8082/infer
Time per request: 80234 [ms] (mean)
```

**原因**：Server-11是单线程处理请求

**解决方案**（高级）：

```cpp
// 在main.cpp中引入请求队列
#include <queue>
#include <mutex>
#include <thread>

std::queue<int> request_queue;  // 客户端socket队列
std::mutex queue_mutex;

// 主线程：接受连接
while (true) {
    int client_fd = accept(server_fd, nullptr, nullptr);

    std::lock_guard<std::mutex> lock(queue_mutex);
    request_queue.push(client_fd);
}

// 工作线程：处理请求
void worker_thread(SimpleInference& inference) {
    while (true) {
        int client_fd;
        {
            std::lock_guard<std::mutex> lock(queue_mutex);
            if (request_queue.empty()) continue;
            client_fd = request_queue.front();
            request_queue.pop();
        }

        handle_request(client_fd, inference);
        close(client_fd);
    }
}
```

**注意**：这需要更复杂的设计，超出Server-11的范围。实际生产环境应使用专业框架（如llama-server）。

### 5.3.1 CPU优化

**调优1：线程数配置**

```cpp
// SimpleInference.h构造函数中

// ❌ 不好：固定值
ctx_params.n_threads = 4;

// ✅ 更好：动态获取CPU核心数
#include <thread>
ctx_params.n_threads = std::thread::hardware_concurrency();

// ✅ 最好：限制最大值，避免过度使用
int max_threads = std::min(
    (int)std::thread::hardware_concurrency(),
    8  // 最多8个线程
);
ctx_params.n_threads = max_threads;
```

```cpp
#include <hiredis/hiredis.h>

std::string cached_infer(const std::string& prompt, int max_tokens) {
    // 1. 生成缓存key
    std::string cache_key = "infer:" + prompt + ":" + std::to_string(max_tokens);

    // 2. 查询Redis
    redisReply* reply = (redisReply*)redisCommand(redis_ctx, "GET %s", cache_key.c_str());
    if (reply && reply->str) {
        std::string cached_result = reply->str;
        freeReplyObject(reply);
        return cached_result;  // 缓存命中
    }

    // 3. 缓存未命中，执行推理
    std::string result = inference.infer(prompt, max_tokens);

    // 4. 存入缓存（TTL=1小时）
    redisCommand(redis_ctx, "SETEX %s 3600 %s", cache_key.c_str(), result.c_str());

    return result;
}
```
