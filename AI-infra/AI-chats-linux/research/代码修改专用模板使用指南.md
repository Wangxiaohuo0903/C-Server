# 代码修改专用模板使用指南

> **版本**: v3.1 (基于 Prefix Tree 优化)
> **日期**: 2025-10-21
> **目标**: 为低算力本地环境提供高效的代码修改助手

---

## 📖 背景

在本地低算力环境下运行大语言模型，**最大的瓶颈是计算速度慢**。通过前缀缓存优化，我们可以：

1. **预先计算**常用模板的 KV Cache（启动时一次性完成）
2. **跨请求复用**这些缓存，避免重复计算
3. **专门针对代码修改场景**设计模板，提升命中率

**核心思想**：如果你经常用 AI 改代码，那就提前把"改代码专用的 System Prompt"算好缓存起来，每次请求直接复用，速度提升 2-3 倍！

---

## 🎯 适用场景

这套模板系统特别适合以下使用场景：

### ✅ 适合的场景
- 经常需要修复代码 bug
- 重构优化现有代码
- 添加新功能到已有代码
- 学习理解陌生代码
- 性能优化和调试
- 代码审查和质量检查

### ⚠️ 不适合的场景
- 闲聊、写文章等非代码任务（模板是代码专用的）
- 从零开始写全新项目（不如用通用模板）

## 🔧 自定义模板

### 修改配置文件

编辑 `warmup_templates_code.json`，添加你自己的模板：

```json
{
  "name": "my_custom_template",
  "category": "自定义类别",
  "prompt": "<|system|>\n你是一个... [详细的 System Prompt]",
  "use_cases": ["场景1", "场景2", "场景3"]
}
```

**关键点**：
- `prompt` 字段必须以 `<|system|>\n` 开头（符合 ChatML 格式）
- 内容越详细，模型表现越专业
- 使用 `\n` 表示换行

### 重新编译和启动

```bash
cd build
cmake --build . --target ai_infra_server_mac
./ai_infra_server_mac
```

服务器会自动加载新的模板配置。

## 💡 最佳实践

### 1. 选择合适的模板

**根据任务类型选择模板**：
- 有编译错误？→ `bug_fix`
- 代码太乱？→ `code_refactor`
- 要加新功能？→ `add_feature`
- 看不懂代码？→ `code_explain`
- 程序太慢？→ `performance_optimize`

### 2. 复制完整的 System Prompt

**重要**：要想命中缓存，必须**完整复制** `warmup_templates_code.json` 中的 `prompt` 字段！

**正确示例**：
```json
{
  "user_message": "<|system|>\n你是一个专业的代码审查和Bug修复专家。你的任务是：\n1. 仔细分析用户提供的代码\n...[完整的 prompt]...<|user|>\n我的代码..."
}
```

**错误示例**（会导致未命中）：
```json
{
  "user_message": "<|system|>\n帮我修代码<|user|>\n我的代码..."
}
```

### 3. 设置合适的解码参数

```json
{
  "max_tokens": 256,      // 代码修改建议通常不需要太长
  "temperature": 0.3      // 低温度保证输出确定性
}
```

### 4. 查看缓存统计

定期检查命中率：
```bash
curl http://localhost:8080/api/cache_stats
```

如果命中率低于 50%，说明你的请求模板和预设模板不匹配，需要调整。

## 🎓 工作原理

### 1. 启动时预热

```
服务器启动
  ↓
读取 warmup_templates_code.json
  ↓
提取所有 10 个 prompt 字段
  ↓
逐个 tokenize（文本 → token 序列）
  ↓
执行一次前向传播，计算 KV Cache
  ↓
将 KV Cache 保存到 Prefix Tree
  ↓
完成预热，等待用户请求
```

### 2. 请求时复用

```
用户发送请求
  ↓
提取 System Prompt 部分
  ↓
在 Prefix Tree 中查找最长匹配前缀
  ↓
如果命中：直接复用 KV Cache（跳过重复计算）✅
如果未命中：正常计算（性能较慢）⚠️
  ↓
继续生成后续 token
  ↓
返回结果给用户
```

### 3. 为什么这么快？

**关键**：System Prompt 的 KV Cache 已经在启动时计算好了！

- **无缓存**：每次请求都要重新计算 System Prompt（80-100 tokens）→ 慢 🐢
- **有缓存**：直接跳过 System Prompt，从用户问题开始计算 → 快 🚀

**性能提升 = 前缀长度 / 总长度**

示例：
- 前缀：89 tokens（System Prompt）
- 用户输入：20 tokens
- 生成输出：50 tokens
- **加速比 = 89 / (20 + 50) ≈ 2.9x** ⬆️

## ❓ FAQ

### Q1: 为什么有时候命中率很低？

**原因**：你的 System Prompt 和预设模板不匹配。

**解决**：完整复制 `warmup_templates_code.json` 中的 `prompt` 字段。

### Q2: 可以混用多个模板吗？

**不建议**。每个请求只能匹配一个模板。如果需求复杂，可以创建一个"综合型"模板。

### Q3: 模板太多会占用内存吗？

**会**，但影响不大。10 个模板大约占用 50-80MB 内存（视模型大小而定）。

如果内存紧张，可以在 `config.max_warmup` 中限制预热数量（例如设为 5）。

### Q4: 可以运行时动态添加模板吗？

**暂不支持**。需要修改 `warmup_templates_code.json` 并重启服务器。

未来版本会支持热加载。
