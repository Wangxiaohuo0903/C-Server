## 一、选题背景与研究意义

### 1.1 研究背景

大语言模型（LLM）的广泛应用正在改变软件开发、内容创作、教育等诸多领域。然而，当前LLM服务主要依赖云端部署，存在以下问题：

1. **成本高昂**：云端API调用费用持续累积（如GPT-4: $0.03/1K tokens）
2. **隐私风险**：用户数据必须上传到云端处理
3. **网络依赖**：需要稳定的网络连接，离线场景无法使用
4. **响应延迟**：网络传输+云端排队导致延迟不可控

**本地部署困境**：虽然小型开源模型（如LLaMA、TinyLLaMA）可以在消费级硬件上运行，但受限于：
- **推理速度慢**：单次对话可能需要数秒甚至十几秒
- **资源占用高**：内存/显存消耗大，影响其他应用使用
- **用户体验差**：无法满足实时交互需求

**研究动机**：能否通过系统优化技术，让普通用户在个人电脑（笔记本、台式机）上流畅运行LLM服务，实现：
- 零成本（无需云端API费用）
- 隐私保护（数据不离开本地）
- 低延迟（亚秒级响应）
- 高可用（离线可用）

### 1.2 研究意义

**理论意义**：
- 探索面向边缘设备的LLM推理优化方法，填补云端优化技术在端侧的适配空白
- 研究资源受限环境下的智能缓存与调度策略
- 为边缘智能与大模型结合提供系统级解决方案

**实际意义**：
- **降低使用门槛**：让没有高性能GPU的普通用户也能使用LLM
- **保护用户隐私**：敏感数据（医疗、法律、个人笔记）无需上传云端
- **节省成本**：个人开发者、小型团队无需支付昂贵的云端费用
- **拓展应用场景**：离线环境（飞机、地铁、偏远地区）也能使用

## 二、国内外研究现状

### 2.1 云端LLM服务优化

当前主流研究主要针对**数据中心GPU集群**场景：

| 系统 | 核心技术 | 适用场景 | 局限性 |
|------|---------|---------|--------|
| **vLLM (SOSP'23)** | PagedAttention内存管理 | A100/H100 GPU集群 | 需要大显存GPU |
| **FlexGen (ICML'23)** | GPU/CPU/磁盘三级存储 | 大模型offloading | 磁盘I/O成为瓶颈 |
| **Orca (OSDI'22)** | 迭代级批处理调度 | 云端多用户服务 | 假设充足的GPU资源 |

**共性问题**：这些系统优化目标是**提升云端数据中心的吞吐量**，而非降低边缘设备的延迟。

### 2.2 边缘LLM推理

少数工作关注端侧部署，但主要聚焦模型压缩：

- **量化技术**（GPTQ, AWQ）：降低精度减少内存占用
- **模型剪枝**：移除冗余参数
- **知识蒸馏**：用小模型模仿大模型

**局限性**：
- 模型压缩会损失精度
- 忽略了**系统层优化**（缓存、调度、内存管理）
- 缺少针对消费级硬件（Apple Silicon、NVIDIA GTX系列）的优化

### 2.3 研究空白

1. **KV-Cache跨请求复用**：现有系统只在单次会话内复用，未考虑多用户/多会话共享
2. **边缘设备调度策略**：云端批处理策略不适用于资源受限的单机环境
3. **统一内存架构优化**：Apple Silicon的统一内存未被充分利用
4. **普通用户友好性**：缺少开箱即用的本地部署方案

## 三、研究目标与内容

### 3.1 研究目标

**总体目标**：设计并实现一套面向消费级硬件的LLM推理优化系统，使普通用户能在本地流畅运行小型开源模型（1-7B参数）。

**具体目标**：
1. **低延迟**：将对话响应时间从数秒降低至**亚秒级**（<1s）
2. **低成本**：支持消费级硬件（8-16GB内存，集成显卡或中低端独显）
3. **高可用**：完全离线运行，无需网络连接
4. **易部署**：提供简单的安装与使用方式

**性能指标**：
- 平均延迟降低 **60%+**
- 吞吐量提升 **2x+**
- 内存占用控制在 **8GB以内**（模型+KV Cache+系统）

### 3.2 核心研究问题

#### 问题1：如何避免重复计算相同的prompt？

**背景**：
- 用户在多轮对话中，每次请求都包含完整历史
- 不同用户常使用相同的system prompt（如"你是一个编程助手"）
- 重复计算这些内容浪费大量资源

**挑战**：
- 如何识别可复用的前缀？
- 如何在有限内存下管理缓存？
- 如何平衡命中率与缓存开销？

**拟采用方法**：设计**跨请求KV-Cache共享机制**（详见3.3节）

#### 问题2：如何在资源受限下提升吞吐量？

**背景**：
- 边缘设备GPU算力有限，难以支持大batch推理
- 用户请求到达时间、长度不一，简单排队导致资源闲置
- 云端批处理策略（固定batch size）不适用

**挑战**：
- 如何动态组batch以提升GPU利用率？
- 如何保证每个请求的响应时间（SLO）？
- 如何结合KV Cache命中信息优化调度？

**拟采用方法**：设计**轻量级动态批处理调度器**（详见3.4节）

### 3.3 研究内容一：跨请求KV-Cache复用

#### 核心思想

不同用户/会话如果使用相同的prompt前缀，可以共享已计算的KV Cache，避免重复计算。

```
场景示例：
用户A: "你是编程助手。帮我写一个Python排序函数"
用户B: "你是编程助手。帮我写一个Python读取文件函数"

共享前缀: "你是编程助手。"  ← 这部分的KV Cache可以复用
```

#### 技术方案

**1. 前缀自动识别**
- 输入：用户完整prompt
- 输出：可复用的前缀部分
- 策略：
  - 多轮对话：提取固定的system prompt + 第一轮交互
  - 单次请求：提取高频出现的模板前缀

**2. 缓存管理**
- 数据结构：哈希表 `<前缀文本, KV Cache指针>`
- 容量限制：根据可用内存动态调整（如32-128个条目）
- 淘汰策略：LRU（最近最少使用）+ 访问频率权重

**3. 底层集成**
- 基于llama.cpp的序列复制API实现零拷贝
- 利用Apple Silicon统一内存避免GPU-CPU数据传输
- 支持部分前缀匹配（Prefix Tree结构）

**预期效果**：
- 命中率达到 **60-80%**（相同system prompt场景）
- 延迟降低 **50-70%**
- 吞吐量提升 **2-3x**

### 3.4 研究内容二：轻量级动态批处理调度

#### 核心思想

根据请求的预估计算量、到达时间、KV Cache命中情况，动态组batch并调度，最大化GPU利用率。

```
传统方式：
Request1 → 处理 → 完成
Request2 →        处理 → 完成  （GPU空闲期长）

动态批处理：
Request1 ┐
Request2 ├─ 组batch → 并行处理 → 同时完成  （GPU利用率高）
Request3 ┘
```

#### 技术方案

**1. 请求分桶（Bucketing）**
- 按预估计算量分类：
  - 短请求（<100 tokens）
  - 中等请求（100-500 tokens）
  - 长请求（>500 tokens）
- 考虑KV Cache命中：命中的请求计算量更低

**2. Batch成形策略**
- 最大等待时间限制（如50ms），避免延迟过高
- 凑够同类请求后立即发送
- 动态调整batch size（根据可用显存）

**3. 优先级调度**
- 短请求优先（快速响应，提升用户体验）
- 长时间等待的请求提升优先级（防止饥饿）
- 结合KV Cache命中率调整权重

**预期效果**：
- 在保证低延迟（<1s）前提下，吞吐量提升 **50-100%**
- GPU利用率从 **30-40%** 提升至 **60-70%**

## 七、预期困难与解决方案

### 7.1 技术困难

**困难1：缓存命中率不稳定**
- 原因：用户prompt多样性高，难以精确匹配
- 解决方案：
  - 实现Prefix Tree支持部分匹配
  - 基于embedding的语义相似度匹配
  - 用户可自定义system prompt

**困难2：批处理调度复杂度高**
- 原因：需要平衡延迟、吞吐、公平性等多目标
- 解决方案：
  - 先实现简单策略（固定batch size）
  - 逐步引入启发式算法
  - 必要时简化为子问题

**困难3：跨平台兼容性**
- 原因：Metal（macOS）、CUDA（NVIDIA）、CPU接口不统一
- 解决方案：
  - 主要在macOS开发，确保核心功能
  - 预留接口抽象层，便于后续适配

### 7.2 时间管理

**风险**：某个阶段耗时超预期，影响整体进度

**应对**：
- 每月设置检查点，及时调整计划
- 优先保证核心功能（KV-Cache复用）
- 批处理调度如时间紧张可简化

本研究旨在解决**普通用户在本地运行LLM的性能瓶颈**问题，通过跨请求KV-Cache复用和轻量级批处理调度两项核心技术，实现：

- **低成本**：无需云端API费用，消费级硬件即可运行
- **低延迟**：响应时间降至亚秒级，接近云端体验
- **高隐私**：数据不离开本地，保护用户隐私
- **易部署**：开箱即用，普通用户也能轻松使用

研究成果将以**开源系统+学术论文**形式发布，为边缘AI、隐私计算、普惠科技提供有价值的参考。
