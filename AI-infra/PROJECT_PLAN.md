## 🔬 技术路线

### 方案一: KV-Cache 前缀缓存（主要方案）

**原理**:
```
用户请求: "给这段Python代码添加注释：\ndef fib(n): ..."
           └─────────前缀──────────┘ └─可变部分┘

如果前缀命中缓存 → 直接加载 KV-Cache → 只推理可变部分
如果未命中 → 正常推理 → 保存前缀到缓存
```

**关键技术**:
- 前缀树（Trie）数据结构
- LRU 缓存淘汰策略
- llama.cpp 状态序列化

**预期效果**:
- 代码修改场景: 命中率 70%+，延迟减少 40%+
- 多轮对话场景: 命中率 50%+，延迟减少 30%+

---

### 方案二: 分布式缓存共享（创新点）

**场景**:
```
边缘节点 A: 处理了请求 "什么是机器学习？"
边缘节点 B: 收到相同请求 → 从节点 A 获取 KV-Cache
           → 避免重复计算
```

**技术挑战**:
1. 缓存序列化/传输开销
2. 节点发现与通信协议
3. 缓存一致性保证
4. 安全性（缓存加密）

**技术方案**:
- 中心化: Redis 存储共享缓存
- 去中心化: P2P gossip 协议

**预期贡献**:
- 边缘计算场景下的创新应用
- 降低总体计算成本 20%+

---

### 方案三: 推测式解码（备选方案）

**原理**:
```
小模型(draft): "The cat sat on the"
                       ↓ 验证
大模型(verify): "The cat sat on the mat"
                ✓   ✓   ✓   ✓   ✓   ✗→修正
```

**适用场景**: 方案一效果不理想时的替代方案
