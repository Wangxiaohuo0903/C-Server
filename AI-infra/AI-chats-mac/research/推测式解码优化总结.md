## 📊 实验结论

### 1. K值优化实验

| K值 | 延迟 | 接受率 | 吞吐 | 评价 |
|-----|------|--------|------|------|
| 3 | 8054ms | 59% | 0.012 | ❌ 太慢 |
| 5 | 4784ms | 72% | 0.021 | ⭐⭐⭐⭐ 高接受率 |
| **7** | **4715ms** | 65% | **0.021** | **⭐⭐⭐⭐⭐ 最优** |

**关键发现**:
- **K=7最优**: 虽然接受率比K=5低7%，但步数少21%，总延迟更短
- **K=3太保守**: 步数过多(56步)，延迟慢71%
- **步数 > 接受率**: 减少步数带来的收益超过接受率下降的损失

### 2. 模型搜索结果

**目标**: 找到比DeepSeek-1.3B更小、更快的Drafter

**搜索结果**:
- ❌ **DeepSeek-Coder系列最小就是1.3B**，无更小版本
- ❌ **Qwen2.5-Coder-0.5B**: 存在，但vocabulary 151,646 ≠ DeepSeek的32,256（不兼容）
- ❌ **Phi-2 / 其他小模型**: Tokenizer不兼容或不是代码专业化

**结论**: **DeepSeek-1.3B已经是同系列最小模型**

### 3. 性能瓶颈分析

**时间分解**:
```
每步总时间: 506ms (理论)
├─ Draft:  326ms (64%) ← 主瓶颈
└─ Verify: 180ms (36%)

实际总延迟: 4715ms (缓存优化后)
完成100 tokens: 22步
```

**瓶颈排序**:
1. **Draft时间太长** (326ms)
   - DeepSeek-1.3B比TinyLlama-1.1B慢70%
   - 占总时间64%
   - **改进空间最大**

2. **Verify批处理开销** (180ms)
   - 批处理7个token有overhead
   - 单token可能只需25ms

3. **未使用高性能推理框架**
   - 依赖llama.cpp默认实现
   - 未使用vLLM/TensorRT等优化

## ⚠️ 当前限制

### 1. 无更小的兼容Drafter

**问题**: DeepSeek-1.3B已是最小，Draft时间326ms无法进一步优化

**影响**: 延迟固定在4.7秒/100tokens，无法突破

**替代方案**:
- ❌ 换用其他系列小模型 → 接受率会暴跌(20% vs 65%)
- ❌ Qwen2.5-Coder-0.5B → Tokenizer不兼容

### 2. 绝对延迟仍然较慢

**对比**:
```
GPT-4 API:        500-1000ms / 100 tokens (快4-9倍)
vLLM优化:         ~3000ms / 100 tokens (快57%)
DeepSeek K=7:     4715ms / 100 tokens
纯CPU贪婪解码:    ~20,000ms / 100 tokens
```

**用户体验**:
- ✅ 短代码片段(100 tokens): 4.7秒 - 可接受
- ⚠️  对话(200 tokens): 9.4秒 - 较慢
- ❌ 长文(500 tokens): 23.5秒 - 很慢

#### 1. 提高K值到9-11 ⭐⭐⭐

**理论**:
```
K=9:
- 步数: 18步 (vs K=7的22步)
- Draft时间: ~370ms (+44ms)
- Verify时间: ~220ms (+40ms)
- 接受率: ~60% (预测，-5%)

延迟估算: 18 * (370 + 220) = 10,620ms (理论)
实际可能: ~4200ms (缓存优化)

vs K=7: 提速11%
```

**风险**: 接受率可能降太多，反而变慢

**建议**: 值得测试K=9

**风险**: 质量略微下降

## 🎓 核心洞察

### 1. 步数 > 接受率

```
K=5: 72%接受率, 28步 → 4784ms
K=7: 65%接受率, 22步 → 4715ms ✅

虽然K=7接受率低7%，但步数少21%
→ 总延迟更短
```

**启示**: 优化目标是最小化 `Steps * (Draft + Verify)`，而非单纯最大化接受率

### 2. Draft速度是关键

```
Draft: 326ms (64%时间)
Verify: 180ms (36%时间)

Draft快10% → 总延迟快6.4%
Verify快10% → 总延迟快3.6%
```

**启示**: 优化Draft收益是Verify的1.8倍

### 3. 同系列模型不保证高接受率

```
Llama同系列:
- Llama-2-7B + TinyLlama-1.1B
- 能力差距: 6.13x
- 接受率: 20.83% ❌

DeepSeek同系列:
- DeepSeek-6.7B + DeepSeek-1.3B
- 能力差距: 5.15x
- 接受率: 64.94% ✅

差异原因: 训练对齐度 > 架构相同
```

**启示**: 选择Drafter时，训练数据对齐比架构兼容更重要

### 4. Tokenizer兼容是硬性要求

```
DeepSeek (32,256) ✅ 可配对DeepSeek
Qwen2.5 (151,646) ❌ 不可配对DeepSeek
```

**启示**: Tokenizer不兼容会直接导致推测式解码失败，没有妥协余地
