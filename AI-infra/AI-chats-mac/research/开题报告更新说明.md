### 5.2 方案二：推测式解码加速单请求推理

#### 5.2.1 核心思想

使用小模型（CPU）快速生成token草案，大模型（GPU）批量验证，实现单请求内部并行加速。

#### 5.2.2 技术方案

**（1）Drafter-Verifier架构**

```
用户请求 → Drafter (TinyLlama 1.1B, CPU/INT4)
              ↓ 生成k=5个token草案
           [t1, t2, t3, t4, t5]
              ↓
         Verifier (Qwen 7B, Metal GPU)
         批量计算5个token概率分布
              ↓
         逐token验证：
           t1: ✅ 接受 (一致)
           t2: ✅ 接受
           t3: ❌ 拒绝 (分歧点)
              ↓
         结果：接受t1,t2，从t3重新生成
```

**（2）异构硬件协同**

- **Drafter（CPU）**：
  - 模型：TinyLlama 1.1B Q4 (~600MB)
  - 线程：4个CPU核心
  - 推理速度：~20 tokens/s

- **Verifier（Metal GPU）**：
  - 模型：Qwen 7B Q4 (~3.5GB)
  - 后端：Metal (Apple Silicon)
  - 批量验证：一次验证5-8个token

- **统一内存优化**：
  - CPU/GPU共享内存，零拷贝传输token
  - 减少drafter-verifier通信开销

**（3）自适应草案长度调度**

```cpp
class AdaptiveKScheduler {
    int current_k = 4;  // 初始草案长度
    std::deque<bool> recent_accepts;  // 滑动窗口(20个)

    int suggestK() {
        double accept_rate = calculateAcceptRate();

        if (accept_rate > 0.8) return 6;       // 高接受率→激进
        if (accept_rate > 0.6) return 5;
        if (accept_rate > 0.4) return 4;       // 平衡
        if (accept_rate > 0.2) return 3;
        return 2;                               // 低接受率→保守
    }
};
```

策略：
- 每20个token调整一次k
- 代码生成任务：高确定性，k=5-6
- 创意写作：低确定性，k=2-3

**（4）批量验证优化**

```cpp
// Verifier批量前向传播
std::vector<int> full_input = prompt_tokens + draft_tokens;

llama_batch batch = llama_batch_init(full_input.size(), 0, 1);
for (size_t i = 0; i < full_input.size(); i++) {
    batch.token[i] = full_input[i];
    batch.pos[i] = i;
    batch.logits[i] = (i >= prompt_tokens.size());  // 只需draft部分logits
}

llama_decode(verifier_ctx, batch);  // 一次性计算所有logits

// 逐个验证
for (int i = 0; i < draft_tokens.size(); i++) {
    const float* logits = llama_get_logits_ith(verifier_ctx, prompt_size + i);
    int best = argmax(logits);

    if (best == draft_tokens[i]) {
        accept_count++;  // 接受
    } else {
        // 拒绝，停止验证
        output_tokens.push_back(best);
        break;
    }
}
