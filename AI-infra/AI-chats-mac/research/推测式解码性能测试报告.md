#### 关键发现

**接受率分析**:
- **实际接受率**: 46.82% (206/440)
- **预期接受率**: 60-70% (理想情况)
- **差距原因**:
  1. TinyLlama (1.1B) 与 Llama-2-7B (6.7B) 模型能力差距较大
  2. 低温度(0.1)下,大模型倾向于更精确的选择
  3. 代码生成任务对精确性要求高

**时间分配**:
- Draft时间: 702.8 ms/step (每次生成5个tokens)
- Verify时间: 136.3 ms/step (批量验证5个tokens)
- **Draft/Verify比例**: 5.16:1

**加速比计算**:
```
理论加速比 = K * acceptance_rate / (1 - acceptance_rate)
          = 5 * 0.4682 / (1 - 0.4682)
          = 2.34 / 0.5318
          = 4.40x (理论上限)

实际加速比 = 17513 / 16645 = 1.05x
```

**实际加速比低的原因**:
1. **Draft模型过慢**: CPU运行TinyLlama耗时702ms
2. **并行度不足**: Draft和Verify串行执行
3. **内存带宽**: 两个模型同时驻留内存

### 3. Token接受模式分析

从调试日志中观察到的接受模式:

```
Step 0-2:   低接受率 (1/5) - 预热阶段
Step 3-29:  中等接受率 (混合) - 探索阶段
Step 30-43: 高接受率 (5/5 + bonus) - 稳定生成阶段
```

#### 典型成功案例 (连续高接受):
```
[DEBUG] Step 36: drafted 5 tokens
[DEBUG] All draft tokens accepted + 1 bonus token from verifier
[DEBUG] Batch verification: accepted 6/5 draft tokens
```
**解释**: 当所有draft tokens被接受时,verifier还会额外生成1个bonus token,实现6个tokens的单步生成 (1.2x baseline)

#### 典型失败案例 (低接受):
```
[DEBUG] Step 30: drafted 5 tokens
[DEBUG] Batch verification: accepted 1/5 draft tokens
```
**解释**: 仅第1个draft token被接受,后续4个被拒绝,需要重新起草

## 🎯 性能瓶颈分析

### 主要瓶颈 (按影响程度排序)

#### 1. **Draft模型速度过慢** (★★★★★)
- **问题**: CPU运行TinyLlama耗时702ms,是瓶颈
- **影响**: 占总时间的 84% (702 / (702+136))
- **根本原因**:
  - TinyLlama全部运行在CPU上 (0/23 layers offloaded)
  - Apple M1 CPU性能远低于GPU
- **解决方案**:
  ```cpp
  // 方案1: 启用GPU加速drafter
  config.draft_n_gpu_layers = 23;  // 全部offload到GPU

  // 方案2: 使用更小的drafter
  // 使用160M的模型替代TinyLlama 1.1B
  ```

#### 2. **接受率偏低** (★★★★☆)
- **问题**: 46.82% < 预期的60-70%
- **影响**: 浪费了约30%的draft计算
- **根本原因**:
  - TinyLlama与Llama-2-7B能力差距大
  - 代码生成任务难度高
- **解决方案**:
  ```cpp
  // 方案1: 降低draft K值
  config.draft_tokens_K = 3;  // 从5降到3

  // 方案2: 提高温度
  temperature = 0.3;  // 从0.1提高到0.3

  // 方案3: 使用更强的drafter
  // Llama-2-1B或Llama-2-3B
  ```

#### 3. **并行度不足** (★★★☆☆)
- **问题**: Draft和Verify串行执行
- **影响**: 无法充分利用CPU+GPU并行能力
- **解决方案**:
  ```cpp
  // 使用流水线并行
  // Step N drafting on CPU
  // Step N-1 verifying on GPU
  ```

### 中期优化 (需要工程改进)

#### 1. CPU/GPU流水线并行
```cpp
// 伪代码
while (n < max_tokens) {
    // 并行执行
    std::thread draft_thread([&]{ draft_tokens = drafter.draft(); });
    std::thread verify_thread([&]{ verified = verifier.verify(prev_drafts); });

    draft_thread.join();
    verify_thread.join();
}
```

**预期加速**: 1.3-1.5x

#### 2. 动态K值调整
```cpp
// 根据实时接受率调整K

    K = std::max(K - 1, 2);  // 降低K值
}
```

**预期收益**: 自适应优化,稳定在最优点
