## 🎯 三大核心创新点

### 创新点1: Token级置信度引导的自适应推测 ⭐⭐⭐⭐⭐

**技术方案**:
- 基于Shannon熵计算每个生成token的置信度
- 动态调整推测窗口大小（n_draft）
- 三级策略：激进（高置信度）、标准、保守（低置信度）

**理论贡献**:
```
置信度定义:
    C(t) = 1 - H(p) / H_max

其中:
    H(p) = -Σ p_i * log2(p_i)  (Shannon熵)
    H_max = log2(|V|)          (最大熵，V为词表)

推测窗口调整:
    n_draft(t) = n_base * α(C(t))

    α(C) = {
        1.5,              if C >= 0.85  (激进)
        0.5 + C,          if 0.6 < C < 0.85  (线性插值)
        0.5,              if C <= 0.6  (保守)
    }
```

**论文章节**:
- 第3章: 基于信息熵的置信度量化方法
- 第4.1节: 置信度引导的自适应推测算法

**实验数据**:
- 置信度分布统计（按任务类型）
- Accept rate vs. 置信度阈值曲线
- 推测窗口调整频率分析

**预期结果**:
- Accept rate提升: 15-25%
- 计算开销: 可忽略（仅entropy计算，~0.1ms per token）

### 创新点2: 任务感知与置信度的联合优化 ⭐⭐⭐⭐

**技术方案**:
将现有的任务分类器与置信度引导结合：
```
最终n_draft = TaskConfig(task_type) × ConfidenceMultiplier(C(t))

示例:
    CODE任务 + 高置信度: 28 × 1.5 = 42
    CODE任务 + 低置信度: 28 × 0.5 = 14
    CREATIVE任务 + 高置信度: 8 × 1.5 = 12
```

**创新性**:
- 首次将宏观任务特征与微观token置信度融合
- 双层优化策略

**论文章节**:

### 创新点3: 边缘计算场景的资源自适应调度 ⭐⭐⭐⭐

**技术方案**:
根据设备资源状况动态调整策略

```cpp
class EdgeResourceAdaptive {
    void adjustStrategy(ResourceStatus status) {
        if (status.available_memory < 1GB) {
            // 低内存模式
            max_n_draft = 16;
            disable_cache = true;
        }

        if (status.battery_level < 20%) {
            // 省电模式
            use_smaller_draft_model = true;
            reduce_verification_frequency = true;
        }

        if (status.cpu_temp > 80°C) {
            // 降温模式
            reduce_n_draft_by(30%);
            increase_sleep_interval();
        }
    }
};
```

**创新性**:
- 首次在推测式解码中考虑边缘设备约束
- 多维度资源感知（内存、电量、温度、网络）

**论文章节**:
- 第5章: 面向边缘计算的资源自适应调度

**实验数据**:
- 不同内存限制下的性能曲线
- 电池消耗对比（vs. 标准推测式解码）
- 热管理效果验证

**预期结果**:
- 内存占用降低30-40%
- 电池续航提升20-30%
- 在资源受限下仍保持合理性能
